Purpose

This project is a professional end-to-end UI automation framework for the ParaBank demo banking application. It demonstrates maintainable Playwright engineering practices rather than only individual browser scripts.

Objectives

  • Implement a reusable Playwright + TypeScript framework.
  • Apply the Page Object Model (POM).
  • Centralize reusable test data and generation logic.
  • Automate the 70 planned manual test cases (TC001–TC070).
  • Cover positive, negative, validation, boundary, robustness and security-oriented scenarios.
  • Provide Playwright HTML and Allure reporting with failure evidence.
  • Maintain traceability between manual test design and automation.
  • Provide a GitHub Actions CI workflow configuration.

Automated Scope

  • Registration: TC001–TC008
  • Login: TC009–TC016
  • Account Overview: TC017–TC023
  • Open New Account: TC024–TC030
  • Transfer Funds: TC031–TC040
  • Bill Payment: TC041–TC049
  • Request Loan: TC050–TC056
  • Navigation & Logout: TC057–TC062
  • Validation & Security: TC063–TC070

Additional framework demonstrations are kept separate from the 70 mapped cases:

  • DD001_invalid_passwords.spec.ts — data-driven authentication examples.
  • DD002_username_boundary.spec.ts — data-driven username boundary examples.
  • Find_Username_Boundary.spec.ts — exploratory investigation supporting the username boundary decision.

Current Framework Characteristics

  • Page Objects inherit from BasePage.
  • Shared browser setup is provided through the project fixture.
  • Registration data is generated through factories and generators.
  • Tests use explicit business-oriented assertions.
  • Playwright HTML and Allure reports are generated from the same execution.
  • Screenshots are captured on failure, videos are retained on failure, and traces are collected on first retry.
  • A deliberate 3-second stabilization wait is used by the shared fixture because the local ParaBank environment demonstrated timing instability during development.

Environment and Limitations

The framework targets a locally hosted ParaBank instance using:

http://localhost:8081/parabank/

The application is a demo system and does not always behave like a production banking application. Some negative/validation scenarios expose application defects or misleading responses. These are intentionally preserved as QA findings rather than changing assertions merely to obtain a green run.

The CI workflow is configured, but a GitHub runner requires a ParaBank instance reachable from the runner before the full UI suite can execute successfully. The workflow configuration is therefore documented as infrastructure-ready rather than claiming a verified remote application environment.

Completion Statement

The planned automation framework scope is implemented. Remaining improvements are optional portfolio enhancements and are not required to consider the project complete.

Future Enhancements

Future work may include Dockerized ParaBank execution, broader browser projects, richer CI publication, and additional portfolio presentation. These are optional enhancements and are outside the completed baseline.
